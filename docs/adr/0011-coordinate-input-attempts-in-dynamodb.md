# ADR-0011: DynamoDBで入力世代と処理attemptを制御する

- ステータス: 承認済み
- 日付: 2026-10-12
- 関連: [Issue #32](https://github.com/Ries630/AzureDataTransformationLab/issues/32)

## 背景

AWS構築を先に完了するため、Azure Phase 6の冪等性実装を待たずにAWS側の重複配送・失敗後再実行・公開を決める必要がある。S3の複数partへの書込は単一トランザクションにならず、処理途中の結果を公開済みと扱うと、再実行や重複受付で不整合になる。

## 決定

DynamoDBの条件付き書込で入力世代の所有者とattempt、共有変換区間を制御し、成功itemが参照するmanifestを公開の正とする。具体的な状態遷移・復旧・公開条件の正は[AWS処理契約](../aws-architecture.md)に置く。

## 検討した代替

- Step Functionsの実行名だけで抑止する: 配送重複の抑止には使えても、失敗後再実行と出力公開の履歴・状態を同じ境界で管理できない。
- S3パスの上書きだけで処理する: 複数partの公開途中失敗と並行更新の所有者を扱う仕組みが別途必要になる。

## 受け入れた代償

処理制御用テーブルとIAM権限が追加される。結果の消費はS3の単純列挙では完結せず、状態itemの参照が必要になる。中断した実行のロックを復旧する手順を維持する。

## 再評価の条件

会社でDynamoDB利用が許可されない場合、または下流がS3の直接列挙だけで公開済みデータを取得する必要が生じた場合に再評価する。
